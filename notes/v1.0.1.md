A security, bug-fix and look-and-feel release. Updating is recommended for
everyone.

## New

- **Group** button, top right. It opens the Serenade group's profile in
  your viewer for the Second Life® world (log in first). If no viewer is
  set up to open Second Life links, it copies the group link for you and
  offers to open the group's page in your web browser instead.
- **Auto-check** box, beside Check for Updates. Untick it and the app no
  longer contacts GitHub by itself when it starts; it checks only when you
  press Check for Updates. It is ticked unless you change it.

## Security

- **Image library updated.** Pillow, which reads your GIFs, is now 12.3.0.
  The previous version had 13 published security flaws, and a file with a
  .gif name but different content inside could reach some of them. The app
  now also refuses to read anything as a GIF unless it really is one.
- **MagicYUV videos are refused.** The video decoder the app relies on has a
  published flaw in the MagicYUV codec (CVE-2026-8461), and no fixed build
  of that decoder is available for this app yet. Before a video is opened,
  the app now reads the file's headers the way the decoder would, and turns
  away any video that uses that codec. It also only opens the usual video
  formats (MP4, M4V, MOV, MKV, WebM, AVI, WMV, FLV, OGV, MPG/MPEG); other
  files are refused with a message, as are 1990s QuickTime movies with a
  compressed header, which the decoder could not open anyway. MagicYUV is a
  rare format, used mostly by screen-capture tools; if you hit any of these
  messages, save the video as an ordinary MP4 and open that.

## Fixes

- **GIFs with very short frame delays** (0.01 s) were read as 100 fps and
  played about ten times too fast in the Second Life® world. Browsers play
  those delays as 0.1 s, and the app now reads them the same way, at 10 fps.
  GIFs with very long delays no longer come out as 0 fps. If you made sheets
  from such a GIF before, make them again.
- **Changing a saved clip's FPS** now also tells you to save its sheet
  again, since the rate is part of the sheet's name.
- **Saving over an existing sheet or GIF** no longer leaves a broken file
  behind if the save fails (a full disk, say); the old file is kept.
- Typing `inf` or a huge number into a number box no longer shows an error,
  and the video preview no longer stops partway through some phone and
  screen recordings.
- **Save Sprite Sheet PNG** could save the previous grid's picture under
  the new grid's name if you clicked it right after changing the grid. It
  now always saves exactly the grid in the file name.
- **Export All** (now called **Export All Sheets & LSL**) could write an
  empty `playlist.lsl` if you changed the playlist while it was running,
  and listed a clip it skipped because all of its frames were off. The
  script now always names exactly the pictures it wrote.
- **Dropping a video and a GIF together** no longer loses the video.
- **Videos recorded in a browser** (WebM files with no length in their
  header) can now be trimmed and extracted, and scrubbed in the preview.
  Before, they gave zero frames, and a range starting more than about a
  second in came from the wrong part of the video.
- **Extracting at more FPS than the video has** (30 from a 24 fps video)
  made the clip play too fast. It now plays at the rate it was taken at.
- **Long names:** the Second Life® world cuts item names at 63 characters,
  which used to cut off the numbers at the end of a sheet's name and break
  the playlist script. Names are now shortened so the numbers survive, and
  clips whose long names differ only near the end (several pieces of one
  video, say) no longer end up with the same sheet name.
- **Custom names** saved with brackets, apostrophes and similar characters
  now appear in the playlist script the way the Second Life viewer
  actually names them.
- **After changing a saved clip's grid or frames**, the playlist script
  kept naming the old sheet with the new grid. It now names the new one,
  and Output Info tells you to save it again.
- **Include All** now also undoes the grid that Trim to Fit picked, so no
  frame is left off the sheet.
- **Animated GIF export:** exports above 50 fps no longer stutter in
  browsers. 50 fps is the fastest a GIF plays reliably, so a 60 fps export
  now plays at a steady 50, and the export message says so. The reported
  playback speed is now the real one, "Fit to size" can shrink tall,
  narrow animations, and exports work when your Windows user name
  contains a `%`.
- **Crop** now reaches the right and bottom edges of the video, and a
  click outside the crop clears it.
- **Very short clips** of one or two frames are no longer refused as empty.
- **Errors** inside the app are now written to the crash log and shown
  once in a message, instead of disappearing without a trace.
- Several smaller fixes to messages and to the preview's play button.

## In the Second Life world

- The playlist script no longer asks for less script memory than it already
  uses. The Second Life simulator ignores a limit like that, which could
  leave the memory setting without effect on a long playlist.
- Sheets with no transparency in them are now saved without an alpha
  channel, so viewers draw them in their normal solid pass rather than
  their transparent one.
- Output Info warns when two clips would get the same sheet name, and when
  a pasted texture UUID is not in the form the Second Life world uses.

## Look and feel

- The window fits your screen when it opens, and with a GIF loaded every
  control fits without scrolling at the normal size. On smaller screens
  the frame strip and the video preview shrink with the window instead of
  squeezing the rest.
- The preview shows transparent areas as a checkerboard, with the grid
  drawn over the sheet, and says what to do when nothing is loaded yet.
- Texture Source now sits on the LSL Script tab, next to the script it
  changes. The script is coloured for reading and no longer wraps in the
  middle of a line.
- Output Info warnings are wrapped and highlighted instead of running off
  the edge.
- Many controls (the frame tools, grid, size, texture source and
  memory) explain themselves when you hover over them.
- The Rename dialog, the Licences window and the update window are dark
  to match.

## Updates themselves

These fixes are part of 1.0.1, so they apply from the next update onward.
This update is still installed by the 1.0.0 updater. If it does not
complete (the app closes and reopens as 1.0.0, or never reopens), or the
app later says 1.0.1 "looks mis-published", close every copy of the app
and download 1.0.1 from this page instead.

- If an update is interrupted (another copy of the app still open, antivirus
  holding the file), it is offered again instead of being skipped for good.
  Each copy of the app keeps its own count, so a copy in another folder no
  longer skips an update because a different copy installed it.
- The update waits for antivirus to finish scanning the download instead
  of giving up, and closing the window while it says "Restarting" no
  longer cancels it.
- A copy whose program file is read-only is sent to the download page
  instead of offered an install that could not finish.
- The update is swapped in all at once, so an interrupted copy can no
  longer leave a broken program behind, and it now works when your Windows
  temporary folder has a space in its path.
- If the author ever withdraws the app and later lifts that, your copy now
  finds out the next time it starts, even if you closed the notice quickly.
- Release notes in the update window are formatted and can be scrolled.
  Long notes used to be cut off.

## If you downloaded before 21 August 2026

Your copy has the same version number as the corrected 1.0.0 build, so it
was never offered that correction. This update replaces it.

## Checking for updates

A few seconds after it starts, while Auto-check is ticked, the app asks
GitHub for the latest release of Serenade GIF and reads a small status
file in its repository, which is where the author posts notices,
including a withdrawal of the app. If a withdrawal was recorded on your
machine, it reads that status file straight away (with Auto-check off, it
asks you first). The requests carry the app's name and version, and your
IP address reaches GitHub. Nothing about your files is sent. See
`NOTICE.txt` and the EULA for the details.

## Downloads

`Serenade.GIF.exe` is the program on its own; the in-app updater uses it.
`Serenade.GIF.rar` adds `NOTICE.txt`, `EULA.txt`, `Guide.txt` and the
`licenses` folder beside it. You do not need the other files to use the
program; they are there for the LGPL:
`ffmpeg-7.1.5.tar.xz` and its `.asc` signature are the source of the
bundled FFmpeg, `zlib-1.3.1-source.zip` and
`mingw-w64-gcc-runtime-source.zip` are the source of the zlib and the
runtimes compiled into it, and `Serenade.GIF.relink-kit.zip` is the program unpacked so you
can run it with your own build of FFmpeg. The script FFmpeg was built with
ships inside the program as `licenses/FFmpeg-build-script.txt`.
